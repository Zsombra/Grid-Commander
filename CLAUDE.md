## Pipeline

This project uses the dev-skills pipeline. Commands and skills are installed globally in `~/.claude/`.

### Available Commands (type / to use)
```
/idea      — Explore a new project idea (greenfield only)
/spec      — Create feature specification
/logic     — Validate product logic
/solutions — Explore architecture options (existing codebase)
/analyze   — Map architecture of existing code
/debug     — Systematic debugging
/document  — Create architecture documentation
```

### Available Skills (invoked automatically or by name)
```
checklist-generator — Creates review checklists in docs/specs/
planner             — Creates implementation plans in docs/plan/
executor            — Implements plans, updates evidence
auditor             — Production gate verification
```

### Pipeline Flow
```
New feature:  /spec → /logic → planner → executor → auditor
Greenfield:   /idea → /spec → /logic → checklist-generator → planner → executor → auditor
Bug fix:      /debug → fix → executor (if plan exists)
Understand:   /analyze → read
Document:     /document
```

## Rules

- Do not modify production code while in planner mode
- Do not skip checklist verification steps
- Do not hardcode project-specific rules — read from docs/specs/ checklists
- All architecture decisions must be documented in decision logs
- Follow the project's review checklists for every change

## Getting Started

If this is a new project with no checklists yet:
1. Run `/idea "your project concept"` to define the idea
2. Run `/spec` to write the feature specification
3. Run `/logic` to validate completeness
4. Run the `checklist-generator` skill to create review checklists
5. Run the `planner` skill to create the implementation plan
6. Run the `executor` skill to build
7. Run the `auditor` skill to verify

If checklists already exist in `docs/specs/`:
1. Start at step 5 (planner) for new features
2. Use `/analyze` or `/debug` for daily work
