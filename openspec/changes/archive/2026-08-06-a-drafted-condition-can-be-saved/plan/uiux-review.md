# UI/UX Review — a-drafted-condition-can-be-saved

| Check | Result | Evidence |
|---|---|---|
| The consequence on screen is the text the token was issued against | PASS | the page renders `proposal.consequence` whole, `whitespace-pre-line`, and composes no second wording of it |
| The whole list is shown, not only the edit | PASS | a numbered list of every key that would be submitted, with the edited one marked added / replaced / removed, above the confirm form |
| A stranded reference is visible before agreement | PASS | its own section, `role="alert"`, saying plainly that it is shown and not blocked |
| Every refusing branch says nothing was written | PASS | drift, compiler refusal, unexpressible draft and unfinished draft each say so, in the words that belong to whoever refused — ours for the two that never reached the platform, the platform's for the one that did |
| A failed read is never an absence | PASS | `WhyNotLoaded` on the `unreadable` branch, subject "this strategy is" |
| The way back exists, and declining does not dump the user on a list | PASS | every branch offers the strategy and the composer; the decline beside the primary goes to `/strategies/[id]` |
| Controls carry the shared treatment | PASS | `BUTTON_PRIMARY` / `BUTTON_SECONDARY`; the only inputs are hidden, which the controls guard exempts by construction |
| The composer still tells the truth about itself | PASS | narrowed to "nothing is saved by this form… saving a draft is a separate act, with its own review and its own confirmation", said both in the body and again at the button — rather than left claiming the page has no way onward |
| The two acts read as two | PASS | the save link appears only once a draft has been tried, and states that the whole list will be shown and agreed to before anything is written |
| A stale link is distinguished from a fresh start | PASS | a removal or a seed naming a condition the strategy no longer defines says so, rather than rendering an empty form |
