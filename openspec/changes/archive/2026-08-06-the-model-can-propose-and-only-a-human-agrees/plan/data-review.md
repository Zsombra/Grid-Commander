# Data Review

Against `docs/specs/DATA_PIPELINE_REVIEW_CHECKLIST.md`. One new table, one
migration, and a set of columns that must **not** exist.

## Schema

`proposals` — id, user id, operation, target, proposed values, recorded at,
status, resolved at.

- [ ] `operation` is a product-operation name from the shared vocabulary, not a
      BattleGrid tool name
- [ ] `target` and `values` are stored as given by the model, verbatim, so the
      page can show what was proposed against what will happen
- [ ] Timestamps are stored with timezone and written from the injected clock,
      never from `now()` in SQL — the codebase already injects a clock so tests
      can move it, and a database default would sidestep that

## Columns that must not exist

This is the `battlegrid-connection` delta expressed as schema:

- [ ] No confirmation-token column
- [ ] No access-token column
- [ ] A test asserts both absences by reading the schema, so a later migration
      cannot reintroduce one quietly
- [ ] The stated property holds: an attacker reading every row can change
      nothing

## Constraints in PostgreSQL, not only in code

Following the pattern `tests/db/` already sets for confirmations and OAuth
state — a fake could only ever agree with the code.

- [ ] Ownership: a proposal belongs to exactly one user, enforced by the
      database
- [ ] Status is constrained to the known set
- [ ] Exercised against a real PostgreSQL in `tests/db/`

## Migration

- [ ] Generated by `npm run db:generate`, committed, and the schema-matches-
      migrations gate passes
- [ ] Applied from the committed journal against an empty database in CI
- [ ] Forward-only; no destructive step on any existing table

## Retention

- [ ] Staleness is computed from `recorded at` against the 72-hour horizon
      (DL-2); it is not a stored flag that could disagree with the timestamp
- [ ] Stale proposals are retained as history and are not actionable
- [ ] No background job deletes anything — the design has no worker, and adding
      one here would be the first
